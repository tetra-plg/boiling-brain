# Migration `v1.3.1`

Invoked automatically by `/update-vault` **step 6** (after **step 5** has propagated the changed template files), for any vault in version < 1.3.1.

- **Part A — scripted journaling step (#145)**: heads-up on what step 5 delivered and on the MCP server reload it needs. Optional `settings.json` allow rule. Informational — **never blocks the verdict**.
- **Part B — journal backlog (#145)**: read-only triage of the source pages whose ingestion left no `wiki/log.md` entry, then an optional, interactive backfill — **never blocks the verdict**.

## Part A — scripted journaling step (#145)

### A0. Context

Step 4 of `/ingest` used to ask the main context to edit `wiki/log.md` and `wiki/radar.md` by hand. A headless run (the `ingest` / `ingest_start` MCP tools) could skip it and still return a clean report with a populated `## Pages` block: the page was written, the journal was not, and nothing noticed. The journal is now a deterministic step:

- **`scripts/wiki-maint/journal-ingest.py`** (+ `test_journal_ingest.py`) — new. `/ingest` writes an ingest report under `cache/ingest-reports/` (frontmatter + the agent's blocks verbatim) and calls the script, which appends the canonical `wiki/log.md` entry and routes the radar items (optional `[verify]`/`[research]`/`[decide]`/`[improve]`/`[watch]` tag, `## Triage` otherwise). Idempotent per source and date.
- **`scripts/mcp/ingest-headless-guard.sh`** — allows `Write`/`Edit` on `cache/ingest-reports/<name>.md` and exactly `python3 scripts/wiki-maint/journal-ingest.py cache/ingest-reports/<name>.md` (charset-anchored).
- **`scripts/mcp/ingest_jobs.py`, `scripts/mcp/mcp-wiki.py`** — a run whose `## Pages` block lists pages but whose source gained no mention in `wiki/log.md` is returned prefixed with `DEGRADED — journal entry missing: …` (sync `ingest()` and `ingest_status()` alike).
- **`scripts/wiki-maint/validate-wiki.py --journal-coverage`** — new opt-in mode, used by `/lint` Pass 1 (see Part B). Without the flag the validator behaves exactly as before: the vault's CI is unaffected.
- **`.claude/commands/ingest.md`**, **`.claude/commands/lint.md`**, **`.claude/agent-output-contract.md`** — updated accordingly.

All of these are template files: step 5 propagated them (new files are pre-checked in its selection). Check that the new script landed:

```bash
test -f scripts/wiki-maint/journal-ingest.py && echo "present" || echo "absent"
```

If `absent`: the file was deselected at step 5 — re-run `/update-vault` and keep it selected; `/ingest` step 4 now depends on it.

### A1. MCP reload heads-up

The `DEGRADED` stamp lives in the MCP server code. If step 5 propagated `scripts/mcp/ingest_jobs.py` / `scripts/mcp/mcp-wiki.py`, the running server still serves the previous code until it is restarted (restart the Claude Code session; quit and reopen Claude Desktop / Cowork). **Step 7** of `/update-vault` already offers this — no extra action here.

### A2. Optional allow rule (interactive)

In an interactive `/ingest`, the first call to the script triggers a permission prompt. To avoid it, propose via `AskUserQuestion` (never edit silently) adding to `.claude/settings.json` `permissions.allow`:

```text
Bash(python3 scripts/wiki-maint/journal-ingest.py *)
```

Skip if the exact string is already present. A decline is fine: the prompt simply appears at the first interactive ingest. Headless runs are unaffected either way (the guard allowlists the call).

### Verdict for `/update-vault`

Part A is **Applied** in all cases: it reports what file propagation delivered and offers a local convenience.

## Part B — journal backlog (#145)

### B0. Context

Runs that skipped the journaling step before this release left source pages with no matching `wiki/log.md` entry — and their radar items were lost with the run's stdout. The new coverage mode finds them.

### B1. Triage (read-only)

```bash
python3 scripts/wiki-maint/validate-wiki.py --journal-coverage
```

It prints one `JOURNAL-MISSING wiki/sources/<x>.md (ingested: <date>)` line per `type: source` page with no `## [<ingested>] ingest |` (or `ingest-<x> |`) entry whose block mentions its `source_path` or links the page, or whose header holds its H1 title — then a `journal coverage: N source page(s) without a log entry` summary. `N = 0` → nothing to do, this Part is done.

Expect some noise on old vaults: batch entries that summarize several sources in one line without linking each page are reported too. That is the intended reading: the log does not say, per page, what was ingested.

### B2. Backfill (interactive, optional)

Show the list grouped by date and ask via `AskUserQuestion` whether to backfill. On yes, for each page (or the subset the user picks), write an ingest report from the page itself — `source` = its `source_path`, `title` = its H1, `agent` = `<first domain>-expert`, `date` = its `ingested:` date, an `## Ingest summary` with `- Pages created: [[sources/<slug>]]` and an empty `## Radar items` (`- N/A`: the original items are not recoverable) — and run `python3 scripts/wiki-maint/journal-ingest.py <report>`. Never invent radar items or pages that the source page does not name.

A decline leaves the backlog in place; `/lint` keeps reporting it.

### Verdict for `/update-vault`

Part B is **Applied** regardless of the backfill outcome: the missing entries are pre-existing vault data, not a template transformation.

## Idempotence

- **A0/A2** are checks and an exact-string-guarded edit — safe to re-run.
- **B1** is read-only. **B2** is idempotent by construction: `journal-ingest.py` writes nothing for a source that already has an entry on the same date (`log=skipped`), and a backfilled page disappears from the next B1 run.

## Logging

Append a migration log entry to `wiki/log.md`:


## Commit

If B2 backfilled any entry (`wiki/log.md` changed):

```bash
git add wiki/log.md
git commit -m "chore: migrate to v1.3.1 (journal backfill)"
```

`.claude/settings.json` (A2) is the vault's local approval file: leave it out of this commit. If nothing changed, skip this commit.
